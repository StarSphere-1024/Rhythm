# 作息数据与快照

作息数据与任务、规则、覆盖和执行历史共同由 `Planner` 持有，并使用相同的串行“先持久化、后发布”规则。原生快照继续存于 SQLite；Web 快照继续使用浏览器本地存储。作息不是任务：打卡不会创建任务、执行记录或重复规则，也不进入任务计划数、完成数、跳过数、完成率、分类次数或任务历史。

## 模型

`RoutinePreferences` 保存每天通用的入睡与起床目标钟面分钟数（0–1439）、睡眠折叠开关和两种打卡入口的独立启用状态。目标缺省为未配置，折叠缺省关闭，两个入口缺省启用。折叠启用时必须同时配置两个不同的时间；相同或缺失的端点不是有效睡眠区间。保存新偏好不会重新解释已有记录。

`RoutineRecord` 是一次打卡的不可变快照：`type` 区分入睡和起床，`targetDate` 是 UTC 午夜承载的所选民用日期，`targetMinutes` 和 IANA `timezone` 是打卡当时的目标快照，`recordedAt` 是 UTC 瞬间。目标日期和记录时间不是同一种时间：前者不表示瞬间，后者必须表示一个 UTC 瞬间。快照不依赖之后修改的偏好或设备时区。

`Planner.recordRoutine` 要求对应入口已启用且目标已配置，并验证时区。相同类型、相同目标日期最多有一条有效记录；重复提交或更正会替换该记录内容并保留其标识，不同类型或不同目标日期互不覆盖。传入的记录时刻会规范为 UTC。`undoRoutine` 只撤销传入记录标识对应的记录，不会影响另一种打卡、其它日期或入口设置。关闭入口只改变偏好，不清除历史；关闭后不会继续接受该类型的新记录。

## 快照版本与迁移

当前完整快照和备份使用 schema version 2，在原有设置、分类、任务、规则、覆盖和执行记录字段之外，包含 `routinePreferences` 对象及 `routineRecords` 列表。解码会严格检查必需字段和类型、分钟范围、日期格式、UTC 日期载体、记录标识唯一性、时区有效性，以及同类记录的目标日期唯一性。未知版本或无效内容会报错，不会重置或部分恢复数据。

有效 schema version 1 快照仍按原有规则完整验证，并映射为默认作息偏好及空作息历史；不会合成或猜测历史记录。导入 v1 是完整替换，后续任何成功变更或导出均使用当前 schema version 2。恢复仍先完整验证，再通过 Planner 的序列化持久化路径整份替换；写入失败不会发布已恢复的状态，已有数据保持不变。

SQLite/Web 使用相同 JSON 快照，不建立单独的作息表或第二套持久化状态。实际 SQLite 文件重开及备份全量恢复由 `sqlite_persistence_test.dart` 覆盖；领域约束、v1 迁移、失败写入和不污染任务统计由 `routine_test.dart` 覆盖。
